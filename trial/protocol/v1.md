This file is the contract between the Go host (`htmlclay`, `internal/managedtrial`, behind the `managedtrial` tag) and the JS service (`hyperclay-local/trial/service.cjs`) for the full-host stage of the managed trial (`plans/shared/host-contract-go-trial/17-managed-trial.md`, `00-meta-plan.md` "The trial"). ## What the full host adds to the native lanes

The native stage ported every Local lane to Go (G6 to G11) and proved each byte for byte against Local with its room authority switched off. The full stage adds back, over RPC, the parts of Local's lanes that need Node:

- **The room authority block** of each write lane: `admit` before the first backup, `settle` at Local's confirmation point.
- **Local's normalization**, which Go lacks by AD1 and AD2 and P8 forbids: `canonicalForWrite(formatHtml(scopeTailwindLink(…)))`, `rebaseStaleSave`, and the conversion-aware split (`document-host.js:236-239`, `344-387`). It runs inside `admit`, because it needs js-beautify and JSDOM and must run before any backup.
- **The structure authority block** of `restructure`: `prepareStructure`, `commitStructure`, `releaseStructure` (`document-host.js:678-723`, `local-authority.js:358-662`), as a structure consultation inside a new Go structure gate.
- **Room-owned recovery writes** (recovered copies, safety versions) as artifacts Go writes and then acknowledges with receipts, so the service records a copy as published only after it exists.
- **The room-owning public routes,** forwarded whole to the service, and **one live hub,** in the service, fed by Go's notices.

Where room code reaches disk today (DeepSeek inventory, 2026-11-10): recovered copies (`local-authority.js:1254-1286`, through `utils/backup.js:193-205`), the checkpoint (`local-checkpoint.js:77-96` to `document-host.js:764-817`), the auto-name rename (`workspace/auto-name.js:217`), the outside-edit rebase (`root-observer.js:252-275`), and legacy sidecar migration inside page-state reads (`page-state-store.js:70-94`). `auto-named.json` is written under `userData`, outside every served root, and stays a Node write.

## Processes

- **Supervisor:** Electron main in a managed build, `trial/driver.cjs` and `trial/sync-driver.cjs` in the trial. Spawns both children, owns no lock, runs the sync engine with the E1 adapter, and runs the quit lifecycle (`workspace/lifecycle.js:58-85`) through `POST /v1/flush` on the service.
- **Go host:** the public listener for every root, canonical resolution, the per-document locks and the structure gate, every filesystem write and every filesystem read under a served root, the data-loss guard, Tailwind, the commit event stream.
- **JS service:** Local's room code (`local-authority.js`, `local-checkpoint.js`, `local-live-data.js`, the live hub, presence, the page API with a live store, the auto-namer) and Local's normalization. **It never reads or writes a served root.** Every read is `GET /v1/read`; every write is a control call or an artifact in an answer.

## Transport and bootstrap

- **Two loopback listeners, one per direction,** HTTP/1.1 on `127.0.0.1` port 0. Each refuses a request whose `Host` is not `127.0.0.1:<own port>`.
- **Bootstrap is one JSON line on stdin** for both children, an inherited pipe as the meta plan requires, chosen over descriptor 3 because Go cannot open an inherited CRT descriptor on Windows and P14 runs Windows. Go: `{"v":1,"secret":"<64 hex>","service":{"url","secret","epoch"}|null}`. Service: `{"v":1,"secret":"<64 hex>","host":{"url","secret","epoch","roots":[{"id","canonicalPath","publicOrigin"}]}}`. `canonicalPath` is the realpath the authority's `registerRoot` keys by (`local-authority.js:1386-1409`). After the first line stdin stays open; EOF means shut down. `--control-fd` stays for the native stage on POSIX. A secret is never an argument, environment variable, file, `READY` field or URL.
- **As built (M10, `trial/supervisor.mjs`, `trial/service-main.cjs`):** the service's bootstrap is two lines, because Go's address exists only after Go starts. The first line is `{"v":1,"secret"}`, answered `READY {"url","epoch","pid"}`. The second is `{"host":{"url","secret","epoch","roots":[{"id","path","url"}]}}`, Go's READY roots as Go printed them, answered `ATTACHED`. The service takes each root's realpath itself.
- **Order:** the supervisor makes both secrets, starts the service (`READY {"url","epoch"}`), starts Go with the service's url, secret and epoch (`READY` plus `"epoch"`), then writes Go's url, secret, epoch and roots to the service. When the supervisor restarts either child, it sends the survivor the new peer with `POST /v1/peer {url, secret, epoch}` (both sides serve it).
- **Auth:** `Authorization: Bearer <receiver's secret>`, constant time; otherwise `401 {"error":"unauthorized"}`.
- **Epochs, both directions checked.** Every request carries `X-Trial-Epoch: <sender's epoch>` and `X-Trial-Peer-Epoch: <receiver's epoch as the sender knows it>`. The receiver answers `409 {"error":"epoch","epoch":"<current>"}` if the peer epoch is not its own, **and** if the sender epoch is not the peer epoch it currently knows. So a delayed request from a dead Go is refused by a surviving service even though it names the service's epoch correctly.
- **Bodies:** JSON; bytes as `{"encoding":"utf8"|"base64","data":"…"}`. A decoded byte field over 64 MiB, or over the public limit of the route it came from, is `413 {"error":"too-large","field":"…"}`.
- **Errors:** `{"error":"<code>","message":"…","retryable":bool}`. A transport failure is never mapped to `refused`.

## Identifiers

- `opId`: 16 to 64 lowercase hex, made by whoever starts a mutation. **Change from the native API:** a reused opId is refused `409 {"error":"op-reused"}` instead of overwriting the earlier outcome (`CONTROL-PROTOCOL.md:159`). Outcomes stay per Go epoch; after a Go restart, every old opId reads `unknown`, which a caller treats as uncertain, never as "never ran".
- `opHandle`: the opId the service sent with a `/v1/commit` or `/v1/checkpoint`. Go echoes it in that write's `admit` and `settle`, so the service finds its own per-write state (the page API's persistent token, the checkpoint capture) by it. `null` for writes that began at Go's public listener.
- `consultId`: 32 hex, made by Go per consultation. Terminal states in the service: `answered`, `settled`, `aborted`. The service keeps a tombstone per consultId for the current Go epoch, so an `abort` that arrives before its `admit` makes that `admit` answer `409 {"error":"aborted"}`.
- `reservation`: opaque, from `admit`, held in service memory (`rooms.reservePage*`). Not a filesystem lock.
- `artifactId`: 16 hex, made by the service per artifact.
- Room key: `canonicalPath`, Go's resolution, sent in every request beside `root` and `name`, so the service never runs a second resolver.

## Lock rules

- **Go holds its document lock, or its structure gate, through a consultation.** That is the meta plan's crossing ("Go resolves and locks the document, … asks JS to prepare …, installs the result, then confirms", `00-meta-plan.md:361`) and where Local's lanes hold `withDocument` while consulting the authority.
- **The service never holds a lock or boundary of its own across a call to Go** (`00-meta-plan.md:360`, "JS never holds a filesystem lock while awaiting Go"). The routes the service owns run Local's `runDocumentWrite` and `withStructureChange` up to their read and render, release, then make the control call, and on `changed` run the handler again from its read. Without this, every page API write deadlocks: the route holds `withDocumentWrite`, `/v1/commit` makes Go call `admit`, and `admit` waits for the same boundary.
- **A handler Go calls never calls Go and never awaits anything that does.** Each handler enters the service's own `withDocumentWrite(canonicalPath)` (or `withStructureChange`) to mint the token every authority call asserts (`assertWriteContext`, `local-authority.js:1134`), and leaves it before answering. Work that needs Go (a checkpoint woken by a confirmation, the auto-name rename) is scheduled after the handler answers; Local already does this (`local-checkpoint.js:154-172`, `auto-name.js:231-241`).
- **A document with an open consultation is frozen for the service's own reconciliation.** Between an `admit` answer and that consultation's `settle` or `abort`, `reconcileDisk`, a cold room open and the relay's floor read for that canonical path wait (bounded by the deadline) or use the bytes Go sent.
- **Go's structure gate** is one process-wide reader and writer gate over the per-document locks, as Local's boundary is (`write-queue.js:40-112`): a structure change is exclusive against every document write and every other structure change; document writes share it. A structure change also carries its page-state moves and drops (below), so no second control call races it.
- **Deadlines.** Each consultation has a deadline, 10 s until M12 measures `admit` and `observe` on the 300 KB page from the last-editor measurement and sets it to at least four times that. On expiry before anything is installed, Go calls `abort`, writes nothing, records the op `refused` with `service-unavailable`, and answers the HTTP client `503 {"reason":"service-unavailable","retryable":true}` with `Retry-After: 1`. Expiry after install is a failed `settle` (Failures, below), never `refused`.

## Go calls the service

### `POST /v1/admit`

Called inside the document lock for every write to a page document (`.html`, `.htmlclay`) in lanes `save`, `replace`, `rebase` and `api`, before the first backup. Local's sources: `document-host.js:236-320` (replace), `344-439` (save), `631-641` (rebase).

```json
{ "consultId": "…", "opId": "…", "opHandle": "…"|null,
  "root": "root-0", "name": "notes.html", "canonicalPath": "/…/notes.html",
  "lane": "save"|"replace"|"rebase"|"api", "origin": "browser"|"data-api"|"checkpoint"|"restore"|"guard-restore"|"template"|"external",
  "current": <snapshot>, "incoming": <bytes as received, before any normalization>,
  "dataLossPrev": <the previous document the native lane reads for the guard>|null,
  "headers": { "if-match", "page-conversion", "page-write", "page-format", "persistent" },
  "edit": false, "safety": false, "explicitCreate": false }
```

`<snapshot>` is what `GET /v1/read` returns (below), read under the same lock. For a page document the request also carries `"versions": [ { "name", "bytes" } ]`: the version files `rebaseStaleSave` would read (`page-rebase.js:43-52`), which are those of the newest 50 in `newestVersionFiles` order (Go's own symlink checks) whose page rev equals the incoming document's, sent only when the incoming document has a page rev, no page state, and a rev other than the stored record's; otherwise `[]`. A handler cannot call Go, so the service's reader serves the stored file and its sidecar from `current` and the version list and bytes from `versions`.

Answers, all `200`:

- `{ "decision":"proceed", "logical": <bytes>, "file": <bytes>, "reservation": "…"|null, "artifacts": [ … ] }`. Both are always present. `logical` is the incoming document after `canonicalForWrite(formatHtml(scopeTailwindLink(…)))`, `rebaseStaleSave`, the conversion-aware `splitWrite` and `checkPageFormatAdmission`; Go stores it through its own `storePageState`, as Local's `placeBytes` does. `file` is the file part with the page format floor stamped (`withPageFormatFloor`), which Go uses where Local uses `fileContent`: the version backup, the unchanged-file check and the data API notify (`document-host.js:360-387`, `473`, `555-564`). **In the full stage Go skips its own `canonicalForWrite`, `splitWrite` and AD2 `stale-page-lineage` refusal for page documents**, because the service has done all three.
- `{ "decision":"refuse", "status": 409|412|428|500|503, "code": "…", "body": {…}, "headers": {…} }`, using Local's code to status map, which the routes own today (`serve_save.go:243-248`, `server.js:3121-3128`, `3467-3486`). Go writes nothing, records the op `refused`, answers the client with that status, body and headers, then calls `abort` with reason `refused` so the service drops anything it held.

`artifacts` are files Local's authority block writes inside the lock, as bytes for Go to write in Local's order before the document: `{ "artifactId", "type":"safety-version", "logical" }` (`document-host.js:411-425`) and `{ "artifactId", "type":"recovered-copy", "root", "name", "logical" }` (`document-host.js:437`, `local-authority.js:1254-1266`). Go names each file with Local's naming and validates type and name against its own resolver; the service never names a path.

Artifacts arrive in batches. A handler that must write files before it can go on answers `{ "pending": true, "artifacts": [ … ] }` in place of its answer. Go writes that batch in order inside the same lock, posts `artifacts-written` with one receipt per artifact (failures included), and takes that call's answer as the handler's next answer: another pending batch, or the original call's final answer. Go never decides on its own that a failed artifact refuses a lane: Local's handler does, as it does today (a missing safety version refuses with `backup-failed`; a failed recovered copy during an edit is logged and the write goes on; a failed recovered copy during a replacement fails the observation). In Local every room-owned recovery write already goes through an injected writer: `publishRecovered` in `createLocalAuthority` (`local-authority.js:40`), and `writeSafetyVersion` and `writeRecoveredCopy` on the lane halves (M1). The service passes writers whose promises settle on the receipt, so a handler, and with it the room and every hold it took, stays suspended until the copy exists. In process the same writers write to disk, so nothing changes.

### `POST /v1/artifacts-written`

Called by Go inside the same lock after writing the artifacts of any `admit`, `settle` or `observe` answer, before the document write or before releasing the lock:

```json
{ "consultId": "…", "receipts": [ { "artifactId": "…", "type": "recovered-copy", "root": "root-0", "name": "notes.html", "version": "<actual file name>"|null, "sha256": "…"|null, "error": null|"…" } ] }
```

Only now does the service record a recovered copy as published, retire or drop the room it came from, and send tabs the `recovered` notice with the actual version name. Until then the room, or the frozen capture the copy was rendered from, is retained with its holds. The answer is the suspended handler's next answer (above). A lost `artifacts-written` is handled like a lost `settle`.

### `POST /v1/settle`

Called by Go inside the lock at Local's confirmation point: after the rename and the etag record, before the API store, the guard and Tailwind (`document-host.js:526-531` then `572-599`). Also for `exact` and `create` writes to page documents (no `admit`; Local's `commitExact` has none), when the service is attached.

```json
{ "consultId": "…", "opId": "…", "opHandle": "…"|null, "root": "root-0", "name": "notes.html", "canonicalPath": "…",
  "lane": "save"|"replace"|"rebase"|"api"|"exact"|"create", "origin": "…",
  "reservation": "…"|null, "outcome": "committed"|"refused"|"failed"|"indeterminate",
  "logical": <bytes>|null, "file": <bytes>|null, "etag": "…"|null, "sender": "server-save"|"sync-engine"|"…",
  "userDriven": true|false|null, "explicitCreate": false, "captureId": "…"|null, "saveId": "…"|null,
  "identity": {dev, ino, size, mtimeNs}|null }
```

On `committed`, the service runs, in Local's order: `rooms.commitPage(reservation)` if any; `confirmKnownWrite(target, logical, token, { sender, persistentToken })` with the persistent token found by `opHandle`, or for `exact` the dirty-room branch to `observeExternal` (`document-host.js:164-175`); the adopt publish when `needsAdoption(logical)` (`:546-554`); the data API notify with `file` and `etag` (`:555-564`); the saved broadcast; the snapshot store's `userDriven` merge (`:606-612`); marking `captureId` saved. **Always** `rooms.releasePage(reservation)` afterwards, on every outcome, because `commitPage` leaves the page reserved (`live-data-rooms.js:567-604`). On any other outcome: release, no confirmation, the room stays dirty.

`identity` is the written file's stat, which the service's reader answers when `confirmKnownWrite` stats the file (S5). Answer `{ "ok": true }`, after any pending batches (`observeExternal` can produce recovered copies, written and receipted before the lock is released). If a step throws after the bytes are on disk, the service still releases, answers `{ "ok": false, "error": "…" }`, and treats the room as unreconciled: Go then follows the failed `settle` path.

**In the full stage, Go's own `Notify` and `Broadcast` hooks publish nothing**: a consulted lane skips its own data API notify and saved broadcast because `settle` does both, and every other notify becomes a notice frame (below). `MarkBrowserSave` stays, because it only keeps Go's watcher from reporting Go's own write. The service is the only publisher, so a tab never gets two morphs for one save.

### `POST /v1/render-checkpoint`

Called by Go inside the lock while serving `POST /v1/checkpoint`. Local's source: `document-host.js:764-808`.

```json
{ "consultId", "opHandle", "root", "name", "canonicalPath", "roomIdentity", "generation", "captureId", "claim": <admission claim the service captured when it sent the checkpoint>, "current": <snapshot> }
```

Answers `{ "kind":"render", "logical", "revision", "captureId", "artifacts" }` or `{ "kind":"clean"|"current"|"refused", "reason", "artifacts" }`. The service validates `claim` here, as Local validates its pre-lock claim inside the lock (`document-host.js:769-771`). On `render`, Go runs its save lane with origin `checkpoint`, `userDriven:false`, `saveId:""`, `dataLossPrev` from `current`, through `commitLocked` (the lock is already held), which calls `admit` and `settle` like any save. Go keeps Local's identity recheck immediately before rename by passing a pre-rename callback to `placeBytes` that compares the file's identity with `current.identity` (`document-host.js:477`); a mismatch refuses `invalid-identity` with nothing replaced.

### `POST /v1/observe`

Called by Go when its watcher reports an outside `add`, `change` or `unlink` of a page document, inside the lock, after the native guard pass. **Go's own writes, restructures and page-state moves never reach `observe`.** Local's source: `root-observer.js:155-315`.

```json
{ "consultId", "root", "name", "canonicalPath", "event":"add"|"change"|"unlink", "current": <snapshot> }
```

Answers `{ "action":"none"|"rebase", "logical": <bytes>|null, "artifacts": [ … ] }`. On `rebase`, Go runs its external-rebase lane with those bytes and `expected: {"type":"checksum","value": current.checksum}` (the native predicate compares `specwire.Etag`, `commit.go:295-313`), which calls `admit` and `settle`. A directory removal is one `observe` per page document Go knew under it, inside the structure gate.

### `POST /v1/structure/prepare` and `POST /v1/structure/settle`

Called by Go inside its structure gate for every `/v1/restructure`, whoever sent it. Local's source: `document-host.js:678-723`, `local-authority.js:358-662`.

- `prepare { consultId, opId, opHandle, root, steps: [ { "kind": "move"|"trash"|"duplicate"|"restore"|"folder"|"empty-trash", "from": {name, location, canonicalPath, isDir, isSymlink}|null, "to": {name, location, canonicalPath}|null } ] }`. `location` is the root's path joined with the name, unresolved; the service builds Local's structure entries (`{location, canonical, isDir, isSymlink}`, `local-authority.js:290-320`) from these and calls `lanes.prepareRestructure` (M3). Answers `{ "decision":"proceed", "holdId" }` or `{ "decision":"refuse", "status", "code" }` with Local's codes (`peers-editing`, `checkpointing`, `destination-exists`, `root-boundary`).
- `settle { consultId, holdId, completed: <number of steps done>, copiedSteps: [ … ], outcome }`. The service runs `lanes.settleRestructure` (`commitStructure(plan, completed)` then `releaseStructure`), and `lanes.admitCopy` per copied step, including `duplicate`'s and `folder`'s admissions (`document-host.js:687-690`, `commands.js:106-107`). Answer `{ "ok": true }`.
- A lost structure `settle` follows the failed `settle` path for every page document the plan touched.

`/v1/restructure` changes to match: each step may carry `"pageState": "move"|"drop"`, applied inside the gate, replacing the separate `/v1/page-state` call the auto-namer and workspace commands make today (`commands.js:186-189`); and two kinds are added, `folder` (create a directory) and `empty-trash`, so no workspace command touches the filesystem from Node (`commands.js:98-116`).

### `POST /v1/abort`

`{ "consultId", "reason": "deadline"|"epoch"|"refused"|"settle-failed"|"failed" }`. The service marks the consultation `aborted`, releases every reservation and structure hold tied to it, discards unreceipted artifacts, and, for `settle-failed`, reconciles each touched room from a fresh `GET /v1/read` before admitting edits, in that order (release, then reconcile, so `rooms.drop` lands, `live-data-rooms.js:812-817`). A running handler rechecks the tombstone after every await and before every effect. Always `200 {"ok":true}`.

### `/v1/route/*`: room-owning public routes

Go forwards these public requests to the service:

- Every live stream form: `GET /_/sync` (including the legacy shared `?s=` form, `server.js:1655`), `GET /live-sync/stream` (`server.js:1636-1718`).
- The relay: `POST /_/sync`, `POST /live-sync/save` (`server.js:1724-1853`). `GET`/`POST /_/sync/data` (`:1570-1571`), `POST /_/presence` (`:1587-1588`).
- `/_/api`, `/_/api/`, `/_/api/<page>` and `?data=` writes on a page where Local's `hasPageStore` holds (`utils/page-api.js:6-9`, a `script[merge][clay~="live"]` with `merge="page"` in the composed document). Go composes the document and applies the same test; other data API requests stay on Go's native route.

Forwarding rules: Go strips every client header named `X-Trial-*`, then sets `X-Trial-Root`, `X-Trial-Canonical`, `X-Trial-Public-Origin` and `X-Trial-Public-Host` from its own resolution, plus the bearer and epochs; the service checks auth on the private headers and rebuilds Local's request context (Origin and Document-URL checks, `server.js:1306-1323`) from the public ones. Bodies and answers stream, with flushes, and the upstream request is cancelled when the client goes away.

A forwarded route that writes a document does so through `POST /v1/commit` (kind `data-api`, `opHandle` = its opId, `expected` from its read). Go reads `prev` under the lock for the guard, as `serve_save.go:227-231` does for a browser save. When Go answers `changed`, the handler runs again from its read, at most twice; the client's `If-Match` and `Page-If-Match` then decide, so a write whose base moved answers 412 or 409 exactly as Local does when the other write landed first. After the third `changed`, `503` retryable. The service maps control answers to Local's statuses, not thrown errors (`server.js:3467-3486`).

The snapshot store moves to the service whole: `settle` carries `userDriven`, the relay writes `html`, and the service serves `POST /v1/snapshot/take { root, name, takeId }`. A repeat with the same `takeId` returns the same answer, so a lost reply does not erase the snapshot the next upload needs. The supervisor's adapter asks the service.

## Go's notices reach the tabs through the event stream

`GET /v1/events` gains `{ "type":"notice", "cursor", "root", "rel", "payload": <Local's notify payload> }`, emitted by Go wherever a native lane or the data-loss guard notifies a path (guard raised and resolved, `guard.go:457-466`; API warnings). The service's events subscriber hands each to its live hub, in cursor order with the commit frames, and replays nothing after a `gap` (a tab reconnecting gets the guard's current state from `GET /_/guard`, as today). There is no second publication RPC.

## The service calls Go

The native control API, plus:

- **`GET /v1/read`** returns a coherent snapshot read under the document lock: the native `{ exists, checksum, bytes }` followed by `fileSha256`, `identity: {dev, ino, size, mtimeNs}`, and for a UTF-8 page document `logical` and `sidecar`, the stored page-state record exactly as `readStored` parses it (`rev`, `tag`, `generation`, `prev`), or `null`, because Local's page-state readers resolve revisions and lineage from that whole record. Go performs any legacy sidecar migration itself, under the lock. The service's `readSaved`, `logicalHtml`, page-state readers and `page-rebase.js` version reads are injected with this and with a read-only history read; they never touch disk.
- **`POST /v1/checkpoint`** `{ opId, root, name, canonicalPath, roomIdentity, generation, captureId, claim }`: as above. Answers `{ "kind":"ok"|"clean"|"current"|"refused"|"indeterminate", "revision"?, "reason"?, "opId", "cursor" }`.
- **`POST /v1/durable`** `{ root, name, checksum }`: under the lock, if the file's checksum still matches, fsync the file, its sidecar and their directories, then answer `{ "durable": true, "checksum" }`; else `{ "changed": true, "checksum" }`. After an `indeterminate` checkpoint the service throws inside the checkpoint host call, so the scheduler's existing transient-failure retry runs (`local-checkpoint.js:54-75`; an indeterminate return schedules no retry), and the next attempt skips the `current` fast path (`document-host.js:798-801`) until `durable` answers `true` for the rendered bytes. One flag per room.
- **`POST /v1/reconciled`** `{ root, name }`: lifts Go's `unconfirmed` mark on a page document (Failures, below).
- **`POST /v1/artifact`** `{ opId, root, name, artifactId, type: "recovered-copy", logical }`: a recovered copy produced outside any consultation; Go writes it under the document lock and answers with a receipt.
- **`POST /v1/commit`** gains `opHandle`. **`POST /v1/restructure`** gains `pageState` per step and the `folder` and `empty-trash` kinds.

## The supervisor calls the service

- **`POST /v1/flush`** `{ deadlineMs }`: runs `checkpointService.flushDirty` and answers `{ unsaved: [ {root, name} ], timedOut: bool }`. Go stays up throughout; the supervisor closes either child only after the quit lifecycle accepts (Retry or Cancel, `workspace/lifecycle.js:58-85`), which is P9's graceful quit.
- **`POST /v1/peer`** as above, and `POST /v1/roots { add|remove }` when a root starts or stops.

## Failures

`unconfirmed` is a Go mark on a page document: Go answers every semantic write to it (`save`, `replace`, `rebase`, `api`, checkpoint, forwarded routes) with the recoverable `503` until the service posts `reconciled`. A `gap` alone is never a barrier.

- **Before `admit` answers, or `admit` reply lost:** deadline, `abort`, nothing written, `503`. A late `admit` effect is fenced by the tombstone.
- **After artifacts, before the document write:** artifacts exist and are receipted; the room is still dirty. If the lane then fails before rename, `settle` with `failed`: release, no confirmation.
- **After the temp file sync, before rename:** the old file stands, the capture stays dirty. Checkpoints keep the pre-rename identity check, so an outside replacement is never overwritten.
- **After rename, before directory sync fails:** `indeterminate`. Go calls `settle` with `indeterminate` (no confirmation), marks the document `unconfirmed`, publishes a `change` frame, and never retries the old bytes. The service reconciles from `GET /v1/read`, establishes durability with `/v1/durable` for checkpoint captures, then posts `reconciled`.
- **`settle`, `observe` or `artifacts-written` fails or times out after the bytes are on disk:** the op stays `committed`; Go marks the document `unconfirmed` and calls `abort { reason: "settle-failed" }` (retried until answered or the service epoch changes). The service releases, reconciles, posts `reconciled`.
- **After `settle`, before the HTTP reply:** the room is correctly confirmed; the client's retry gets 412, as on Local.
- **A control reply lost (service or supervisor to Go):** never resend. `GET /v1/op/<opId>`: `committed` or `indeterminate`, reconcile from `GET /v1/read` and the event stream; `running`, wait; `unknown` in the same Go epoch, submit again with a new opId after a fresh read shows `expected` still holds; `unknown` after a Go restart, reconcile first.
- **Service down or not attached:** semantic writes, checkpoints, structure changes and forwarded routes answer the recoverable `503`. `/_/meta` keeps announcing the full extension list, because P12 says no capability is downgraded. `exact`, `create`, uploads and page-state writes proceed and mark touched page documents `unconfirmed`. When the service returns, Go sends it a `gap` and the `unconfirmed` list.
- **Go restart:** a new Go epoch. The service releases every reservation and structure hold of the old epoch, treats every room with an unreceipted artifact as still dirty, and reconciles every open room from disk before admitting edits. A recovered copy Go wrote but never receipted may be written again: a duplicate copy, never a lost one. The sync engine resumes with a `gap` and runs a full inventory; `upload()` still refuses any path held in `conflicts.json` (`sync-engine/reconcile/execute.js:213`).
- **Service restart:** Go sees the new epoch, marks every page document `unconfirmed`, and lifts each as the new service reconciles it. Rooms of the dead service are rebuilt from disk and reconnecting clients; their unsaved edits are lost exactly as when Local's process dies today, which P9's injected failure measures.

No durable operation journal: Go is the only writer, rename is atomic, the sidecar's `prev` record covers a sidecar written before its file (`page-state-store.js:60-66`), receipts close the artifact gap inside the lock, and the `unconfirmed` barrier closes it across restarts.

## Seams in Local (M1 to M5), each behavior preserving in process

- **S1, the authority block and normalization per lane.** Extract `admitSave`, `admitReplace`, `admitRebase`, `admitApi` (normalization, stale rebase, format admission, keepState, reservation, artifacts) and `settleWrite` (confirmation, adopt, notify, broadcast, snapshot merge, release) from `document-host.js:164-175`, `236-320`, `344-439`, `526-616`, `631-641`, plus `renderCheckpoint` from `764-808`. In process the lanes call them and write and receipt the artifacts themselves, so Local's own `document-host` tests prove nothing changed.
- **S2, the room-owning routes as a factory** `{ ctx, authority, documentHost, boundary }`, mounted by `createApp` in process and by the service. `boundary: 'held'` keeps Local's shape (the in-process host holds `withDocumentWrite` across `commitDocument`); `boundary: 'released'` releases before the control call and reruns the handler on `changed`.
- **S3, the observer's authority half** (`root-observer.js:155-315`, `add` included) as functions of `(event, snapshot)`, no chokidar.
- **S4, recovery in two phases.** No refactor: every recovered copy and safety version already goes through an injected writer (`publishRecovered`, `writeSafetyVersion`, `writeRecoveredCopy`), and a writer that returns a promise settled by Go's receipt suspends the handler between rendering and recording, which is the two phases. M2 pins this with a test: while a deferred `publishRecovered` is pending the room is kept, recovering and held; resolving it completes the replacement with the receipt's version; rejecting it keeps the room recovering for the next observation.
- **S5, injected reads.** One reader scope (`src/main/document-reader.js`, `AsyncLocalStorage`): the leaf reads of the lane halves and the authority (`readStored` and the legacy sidecar read in `page-state-store.js`, the stored file and version reads in `page-rebase.js`, the default `readSaved`, `confirmKnownWrite`'s stat, `admitReplace`'s default current read, the version list `prepareSave` passes) call `reader()`, which is the disk outside any scope. The service runs each handler inside `withReader(snapshotReader, …)`, where `snapshotReader` answers from the call's snapshot (`current`, the settle identity) and refuses any path it was not given, because a handler never calls Go (deadlock: Go holds the lock).
- **S6, structure.** `lanes.prepareRestructure`, `lanes.settleRestructure` and `lanes.admitCopy` (M3, `deb7a55`) from a step list. The workspace commands and the auto-namer are not composed in the service ("Not in v1").
- **S7, checkpoint and quit.** The checkpoint host call reaches Go through the adapter (gaining `checkpoint`); an indeterminate result throws; `flushDirty` reachable by `POST /v1/flush`.

## Answers to the three open questions

- **Call `admit` for every page write.** It is where Local's normalization runs (AD1, AD2), where format admission consults connected editors, and where adoption and lineage consult the room. Only the service knows which rooms exist. If the round trip ever matters, the service answers fast; Go never decides to skip.
- **Move the live layer whole,** with Go's notices arriving as `notice` frames on the event stream. Two hubs would give two views of which tabs are on a document.
- **No service-computed digests.** Go writes each artifact, records its sha256 and actual name, and returns both in a receipt; the service acts only on receipts.

## Decided while building (M7 to M10)

- **The checkpoint carries no claim.** `/v1/checkpoint` and `/v1/render-checkpoint` carry no claim or `captureId`: the adapter keeps the admission claim by `opHandle` in the service, and the render handler validates it inside its boundary, as Local's checkpoint does. Local never marks a capture saved by id, so `captureId` stays null.
- **Observe sees Go's own writes.** Go sends every page-document event, including its own writes, and the service judges its confirmed writes `self` (M7f).
- **Observe reads history from disk.** Go sends no `versions` with observe, so the service reads the document's version history read-only from disk for that call.
- **Outside a consultation the service only reads.** Its reader serves Go's snapshot until settle and the disk afterwards, read-only.
- **Exact and create writes are refused while a document is unconfirmed,** and a failed settle answers `indeterminate` (M7d).
- **`folder` and `empty-trash` are not consulted** (M7g): no room is keyed by a folder, and the trash holds no open room.
- **A thrown render or observe answers `failed`,** never a success-like kind, so Go treats the call as failed and Local's scheduler retries.
- **A restore adds two version files:** the safety version from the artifact loop, then Go's lane backup of the restored content.
- **A refused restore says so.** A version restore or guard restore the service refuses answers the refusal's status, and the guard keeps its incident (`htmlclay` `368d137`). Before the fix, both answered as restored while nothing was written.
- **Local's checkpoint answers `ok` when its save was refused,** and Go mirrors that quirk except for 503 refusals, which stay retryable.
- **Admit falls back to Go's logical read.** Go's `/v1/commit` body has no `dataLossPrev`, so a page API write's admission takes `current.logical`, the same logical bytes Local passes (`server.js:3384-3385`). Without it, every page-store data API write through Go was refused 428 (M9c).
- **Go's own data API notice is the service's.** With a service attached, every `.html` write is consulted, so the "was updated through the data API" warning comes from Local's settle lane in the service, not from Go's native branch (`commit_lanes.go:268-288`). Go's guard notices still arrive as `notice` frames.
- **Fault points (M12a, `htmlclay` `36c61b3`):** `POST /v1/fault` on Go arms `kill-before-rename`, `kill-after-rename`, `durable-fail` or `drop-reply` for one logical path and a count, for P9 and P12.
- **An unproven checkpoint keeps its room dirty (M11c).** When a checkpoint's settle comes back `indeterminate`, the service marks the document before Go answers the adapter. While the mark stands, observe applies nothing from the file, and the adapter's next checkpoint first calls `/v1/durable` on the current bytes, throwing if the proof fails so the scheduler retries. Without the mark, Go's watcher reported the checkpoint's own file as an outside edit, the room reconciled its edits from it (`live-data-rooms.js:446`) and turned clean, and P9 saw a disk that could not sync checkpoint cleanly. `durable-fail` also fails `/v1/durable` (`htmlclay` `a9be7f4`).

**Gaps recorded, no fix:**

- **A failed observe does not mark the document unconfirmed.** Nobody loses work: Go's If-Match and the checkpoint's `reconcileDisk` both catch the stale state.
- **A failed structure settle is not reconciled per document** in v1.
- **An outside edit while a checkpoint is unproven reaches tabs late:** observe skips it, and the next checkpoint's `reconcileDisk` applies it. If the scheduler's retries are spent, that waits for the next flush, edit or departure.
