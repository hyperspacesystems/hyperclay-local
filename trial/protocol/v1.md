# Managed trial protocol v1: Go host and JS service (M19, full-host stage)

Status: draft for review (M0, 2026-11-10). Nothing in M1 to M12 starts until two review seats have read this and the coordinator has merged their findings.

This file is the contract between the Go host (`htmlclay`, `internal/managedtrial`, behind the `managedtrial` tag) and the JS service (`hyperclay-local/trial/service.cjs`) for the full-host stage of the managed trial (`plans/shared/host-contract-go-trial/17-managed-trial.md`, `00-meta-plan.md` "The trial"). It extends the native control API that already exists (`htmlclay/internal/managedtrial/CONTROL-PROTOCOL.md`); nothing in that file changes meaning.

## What changed since the two planning seats

- **Go now runs every commit lane natively.** When the Opus and Astra seats designed M19 (2026-11-09), the Go host had no save lane, so both routed every semantic write through a JS `prepare` that would run Local's whole save lane minus the writes. The native stage has since ported every lane (G6 to G11: save, replace, external rebase, restore, guard restore, data API, uploads, sync download, create, restructure, page state, Tailwind), each judged byte for byte against Local's real server with its room authority switched off.
- **So the JS service is needed only where Local touches a live room.** Local's lanes consult the room authority in one block each, and Go's native lanes are exactly Local's lanes with that block off. The full-host stage adds that block back over RPC and moves the room-owning routes to the service. This is much smaller than either seat's `prepare` for every write, and it keeps one implementation of every lane (Go's), already proven.
- **Where room code reaches disk** (DeepSeek inventory, 2026-11-10, verified against the cited lines): recovered copies (`local-authority.js:1254-1286`, through `utils/backup.js:193-205` into `.hyperclay/recovered/<stem>/`), the checkpoint (`local-checkpoint.js:77-96` to `document-host.js:764-817`, which runs the save lane), the auto-name rename (`workspace/auto-name.js:217`, a structure change) and the outside-edit rebase (`root-observer.js:252-275`, a host commit). `local-checkpoint.js`, `@panphora/clayjs/server/rooms` and the page compactor write nothing themselves. `auto-named.json` is written under `userData`, outside every served root, and stays a Node write.

## Processes

- **Supervisor:** Electron main in a managed build, `trial/driver.cjs` and `trial/sync-driver.cjs` in the trial. It spawns the JS service and the Go host, owns neither lock, and runs the sync engine with the E1 adapter (`trial/go-document-host.cjs`) as today.
- **Go host:** owns the public HTTP listener for every root, canonical resolution, the per-document and structure locks, every filesystem write under a served root, the data-loss guard, Tailwind, and the commit event stream. Unchanged from the native stage except where this file says otherwise.
- **JS service:** a plain Node process running Local's own room code: `local-authority.js`, `local-checkpoint.js`, `local-live-data.js`, the live hub (`livesync-hyperclay`) with the authority's stream handlers, presence, and the page data API when a page has a live store. It writes no file under a served root. Every write it wants comes back to Go either inside an answer (artifacts, below) or as a control API call.

## Transport and bootstrap

- **Two loopback listeners, one per direction,** HTTP/1.1 on `127.0.0.1` port 0: Go's control listener (exists) takes calls from the service and the supervisor; the service's listener takes calls from Go. Neither binds anything else. Both refuse a request whose `Host` is not `127.0.0.1:<own port>`.
- **Bootstrap is one JSON line on stdin,** for both children, because Go cannot open an inherited descriptor 3 on Windows (`os.NewFile` takes a handle there, not a CRT descriptor) and P14 includes a Windows pass. Go: `{"v":1,"secret":"<64 hex>","service":{"url":"…","secret":"<64 hex>"}|null}`. Service: `{"v":1,"secret":"<64 hex>","host":{"url":"…","secret":"<64 hex>","roots":[{"id","path"}]}}`, written after Go's `READY`. After the first line, stdin stays open and EOF means shut down, as the native stage already does. `--control-fd` stays for the native stage on POSIX. A secret is never an argument, an environment variable, a file, a `READY` field or a URL.
- **Order:** the supervisor makes both secrets, starts the service (it prints `READY {"url","epoch"}` once listening), starts Go with the service's URL and secret in its bootstrap line (Go prints the native `READY` plus `"epoch"`), then writes Go's URL, secret and roots to the service's stdin.
- **Auth:** every request carries `Authorization: Bearer <the receiver's secret>`, compared in constant time. A wrong or missing secret is `401 {"error":"unauthorized"}`.
- **Epochs:** each process makes a random 16 hex epoch at start. Every request carries `X-Trial-Epoch: <sender's epoch>` and `X-Trial-Peer-Epoch: <the receiver's epoch as the sender last saw it>`. A request whose peer epoch is not the receiver's current one is `409 {"error":"epoch","epoch":"<current>"}`. That is how a restart of either side invalidates everything in flight.
- **Bodies:** JSON. Bytes travel as `{"encoding":"utf8"|"base64","data":"…"}`, the native rule (`CONTROL-PROTOCOL.md`, Transport). A decoded byte field over 64 MiB, or over the public limit of the route it came from, is `413 {"error":"too-large","field":"…"}`.
- **Errors:** `{"error":"<code>","message":"…","retryable":true|false}` with an HTTP status. A transport failure is never mapped to `refused`.

## Identifiers

- `opId`: 32 hex, made by whoever starts a mutation (Go for an HTTP write, the service or supervisor for a control call). A caller never reuses an opId. Go keeps outcomes per its epoch (`GET /v1/op/<opId>`, native).
- `consultId`: 32 hex, made by Go for each call into the service that may leave state behind (a reservation, a pending recovered copy). Valid only inside the Go epoch and the document lock that issued it.
- `reservation`: an opaque string the service returns from `admit` when it reserved a page in a room (`rooms.reservePage`, `reservePageInitial`, `reservePageReplacement`). It lives in the service's memory, not in Go and not on disk. It is not a filesystem lock.
- Cursor: `<goEpoch>:<seq>`, native.

## The lock rule, and why it cannot deadlock

- **Go holds its own document lock while it consults the service,** exactly where Local's lanes hold `withDocument` while they consult the authority (`document-host.js:364-439`, `526-530`, `764-817`). The lock never leaves Go: the service never receives, holds or releases a Go lock, and Go never waits on a service lock. This is the meta plan's "no lock is held across the process boundary" read as "no process holds a lock on the other's behalf".
- **A handler the service runs for Go (`admit`, `settle`, `render-checkpoint`, `observe`) never calls Go and never awaits anything that calls Go.** Work it starts that needs Go (a checkpoint woken by a confirmation, `local-authority.js:1192`; an auto-name rename) is scheduled to run after the handler answers, and reaches Go later as an ordinary control call that queues behind Go's lock. Local already has this shape: `checkpointService.wake` is not awaited inside the boundary, or the in-process lock would deadlock too.
- **Every consultation has a deadline of 10 s.** On expiry Go calls `abort` for the `consultId`, writes nothing, records the op as `refused` with reason `service-unavailable`, and answers the HTTP client `503 {"reason":"service-unavailable","retryable":true}` with `Retry-After: 1`. A late answer for an aborted `consultId` is ignored.
- **Write order inside the lock does not change.** Go performs the native lane's steps in Local's order; the service only contributes decisions and bytes at the two points Local's authority block does.

## Go calls the service

### `POST /v1/admit`

The pre-write half of the authority block, called by Go inside the document lock for every write to a page document (`.html`, `.htmlclay`) in the lanes `save` (browser save, data write, checkpoint origin), `replace` (restore, guard restore, template reset) and `rebase` (external rebase), before the first backup. Local's sources: `document-host.js:364-439` (save), `244-320` (replace), `631-641` (rebase).

```json
{ "consultId": "…", "opId": "…", "root": "root-0", "name": "notes.html",
  "lane": "save" | "replace" | "rebase", "origin": "browser" | "data-api" | "checkpoint" | "restore" | "external",
  "current": { "exists": true, "logical": { "encoding": "utf8", "data": "…" }, "fileSha256": "…" },
  "incoming": { "logical": { "encoding": "utf8", "data": "…" } },
  "headers": { "if-match": null, "page-conversion": null, "page-write": null, "page-format": null, "persistent": null },
  "edit": false, "safety": false }
```

Answers, all `200`:

- `{ "decision": "proceed", "logical": <bytes>|null, "floor": "<page format floor>"|null, "reservation": "…"|null, "artifacts": [ … ] }`. `logical` is the incoming document after format admission when it changed (`checkPageFormatAdmission`, `document-host.js:385-387`), else `null`. Go continues the native lane with these bytes, stamping `floor` as `withPageFormatFloor` does.
- `{ "decision": "refuse", "status": 409, "code": "unsaved-edits" | "page-conflict" | "…", "message": "…" }`. Go writes nothing, records the op `refused`, and answers the client with that status and Local's body for that refusal.

`artifacts` are files Local's authority block writes inside the same lock, returned as bytes for Go to write in Local's order before the document:

- `{ "type": "safety-version", "logical": <bytes> }`: the room's unsaved edits as a version of the document (`document-host.js:411-425`, `createBackup`), written to `.hyperclay/versions/<name>/` with Local's naming.
- `{ "type": "recovered-copy", "root": "root-0", "name": "<rel>", "logical": <bytes> }`: a recovered copy (`recoverUnsavedEdits`, `document-host.js:437`, and `local-authority.js:1254-1266`), written to `.hyperclay/recovered/<stem>/` with Local's naming. One per route `recoveryRoutes` names (`local-authority.js:1236-1252`); a route in a root Go does not serve is dropped and counted.

Go validates every artifact's type and name against its own resolver; the service never names a destination path.

### `POST /v1/settle`

The post-write half: Go calls it inside the lock after the lane finishes, with what happened, so the room learns the result in disk order (`document-host.js:313-320`, `526-530`, `616`; `confirmExact`, `164-175`).

```json
{ "consultId": "…", "opId": "…", "root": "root-0", "name": "notes.html",
  "lane": "save" | "replace" | "rebase" | "exact" | "create",
  "reservation": "…" | null, "outcome": "committed" | "refused" | "failed" | "indeterminate",
  "stored": <logical bytes>|null, "etag": "…"|null, "sender": "server-save" | "sync-engine" | "…",
  "live": { "html": <bytes>, "sender": "…", "lane": "saved" | "live" } | null }
```

- On `committed`: the service runs `rooms.commitPage(reservation)` when there is one, then Local's confirmation for that lane (`confirmKnownWrite`, or for `exact` the dirty-room branch to `observeExternal`), then publishes `live` to its subscribers. Answer `{ "ok": true, "artifacts": [ … ] }`; `observeExternal` can produce recovered copies, which Go writes before releasing the lock.
- On anything else: `rooms.releasePage(reservation)` and no confirmation, so a dirty room stays dirty. Answer `{ "ok": true, "artifacts": [] }`.
- `exact` and `create` writes skip `admit` (Local's `commitExact` has no admission) but still call `settle` when the service is attached, because a room may be open on that document.

### `POST /v1/render-checkpoint`

Called by Go inside the lock while serving a `POST /v1/checkpoint` from the service (below). Local's source: `document-host.js:764-808`, the part before `commitSave`.

```json
{ "consultId": "…", "root": "root-0", "name": "notes.html", "roomIdentity": "…", "generation": "…",
  "current": { "exists": true, "logical": <bytes>, "fileSha256": "…", "identity": { "dev": "…", "ino": "…", "size": 0, "mtimeNs": "…" } } }
```

Answers: `{ "kind": "render", "logical": <bytes>, "revision": "…", "captureId": "…" }`, or `{ "kind": "clean" | "current" | "refused", "reason": "…"|null }`, with `artifacts` from `reconcileDisk` on any of them. On `render`, Go runs its native save lane with origin `checkpoint`, `userDriven: false`, `saveId: ""`, and `dataLossPrev` set to `current`, which calls `admit` and `settle` like any save. `settle` carries `captureId` so the service marks exactly that capture saved.

### `POST /v1/observe`

Called by Go when its watcher reports an outside change to a page document, inside the lock, after the native data-loss guard pass (`CONTROL-PROTOCOL.md`, The watcher). Local's source: `root-observer.js:161-315` with the authority present.

```json
{ "consultId": "…", "root": "root-0", "name": "notes.html", "event": "change" | "unlink",
  "current": { "exists": true, "logical": <bytes>, "fileSha256": "…" } }
```

Answers `{ "action": "none" | "rebase", "logical": <bytes>|null, "artifacts": [ … ] }`. On `rebase`, Go runs its native external-rebase lane with those bytes and `expected` set to `fileSha256`, which calls `admit` and `settle`. A directory removal is one `observe` per document Go knew under it, inside the structure lock (`local-authority.js:1362-1384`).

### `POST /v1/abort`

`{ "consultId": "…", "reason": "deadline" | "epoch" | "failed" }`. The service drops any reservation or pending artifact tied to that consultation. Always `200 {"ok":true}`, including for an unknown id.

### `/v1/route/*`: the room-owning public routes

Go forwards these public requests to the service unchanged (method, path, query, headers, body) with `httputil.ReverseProxy`, streaming the answer back with flushes and cancelling the upstream request when the client goes away:

- `GET /_/sync` and `GET /live-sync/stream` in every form (`server.js:1636-1718`): with an authority, Local answers every stream through the authority (`handleSharedSyncStreamV2`, `handleAuthorityLiveStream`), so the live layer moves to the service whole. Go's own live hub (G9a) stays for the native stage only.
- `POST /_/sync` and `POST /live-sync/save` (the relay, `server.js:1724-1853`), `GET` and `POST /_/sync/data` (`server.js:1570-1571`), `POST /_/presence` (`server.js:1587-1588`).
- `GET` and `POST /_/api/<page>` and `?data=` writes on a page whose sidecar says it has a live store (`server.js:3290-3494`, `hasPageStore`). Other data API requests stay on Go's native route.

A forwarded route that needs a document write makes it through the control API (`POST /v1/commit` with kind `data-api`, and an `expected` checksum from a fresh `GET /v1/read`). When Go refuses it with `changed`, the service rereads and retries at most twice, then answers the client `503` retryable. Local never sees this race because it holds the lock across the whole route; the retry keeps the client's view the same.

The snapshot hand-off for platform sync moves with the relay: the service serves `POST /v1/snapshot/take` (G9b's shape) and the supervisor's adapter asks the service instead of Go.

## The service calls Go

The native control API (`CONTROL-PROTOCOL.md`), plus:

- `POST /v1/checkpoint` `{ "opId", "root", "name", "roomIdentity", "generation" }`: Go takes the document lock, reads current bytes and identity, calls `render-checkpoint`, and continues as above. Answers Local's checkpoint result `{ "kind": "ok" | "clean" | "current" | "refused", "revision"?, "reason"?, "outcome"?, "opId", "cursor" }`. An `indeterminate` save inside it answers `{ "kind": "indeterminate" }`, and the service keeps the room dirty: it must not take the `isCheckpointCurrent` fast path (`document-host.js:798`) on the next attempt until a fresh read proves the rendered bytes are durable.
- `POST /v1/artifact` `{ "opId", "root", "name", "type": "recovered-copy", "logical": <bytes> }`: a recovered copy the service produces outside any Go consultation (an observer path after a gap, below). Go writes it under the document lock. Answers `{ "outcome": "committed", "version": "recovered-<file>" }`.
- `GET /v1/read` gains `"fileSha256"` and `"identity"` fields. Existing callers ignore them.
- `POST /v1/restructure` gains nothing: the auto-name rename and every workspace command already go through it.

## Failures

- **Lost request or reply, either direction.** The caller never resends a mutation on a transport error. It asks `GET /v1/op/<opId>`: `committed` or `indeterminate` means the write happened or may have, and the caller reconciles from `GET /v1/read` and the event stream; `unknown` means Go never saw it, and the caller may submit again with a new opId only after a fresh read shows its `expected` still holds; `running` means wait for the commit frame.
- **Failure before rename** (an artifact write, backup, sidecar, temp write, file sync): nothing replaced; Go calls `settle` with `failed`, so the reservation is released and the room stays dirty.
- **Failure after rename** (directory sync, `utimes`, the guard state write): `indeterminate`. Go calls `settle` with `indeterminate`, never retries the old bytes, and publishes a `change` frame so every reader rereads. The service does not confirm.
- **`settle` itself fails or times out after a committed write.** The bytes are on disk; the op stays `committed`; Go marks the document `unconfirmed` and sends the service a `gap` on its events subscription, after which the service reconciles that room from disk before admitting new edits (`reconcileDisk`), as Local does for an outside edit.
- **Service down or not attached.** Writes to page documents in `save`, `replace` and `rebase`, checkpoints, and every forwarded route answer the recoverable `503`. `/_/meta` keeps announcing the full extension list, because P12 says no capability is downgraded: a client told it lost `live-data` would fall back to whole-document saves. `exact`, `create`, uploads, structure and page-state writes proceed, and Go marks each touched page document `unconfirmed`. When the service returns, Go sends it a `gap` and the list of unconfirmed documents; the service reconciles each before admitting edits.
- **Go restart.** A new Go epoch: every `consultId` and reservation from the old epoch dies, a late `settle` or answer is refused with `409 epoch`, and the service releases every reservation it held for the old epoch. The service's events subscription and the sync engine's both resume with an old cursor and receive `gap`. The service reconciles every open room against disk. The sync engine runs a full inventory through L4, which still refuses `upload()` for any path held in `conflicts.json`, because the hold lives in `userData` and the engine checks it (`sync-engine/reconcile/conflicts.js:25-56`).
- **Service restart.** Go sees the new service epoch on its next call (or a `409 epoch`), aborts nothing it has not already finished, and treats every page document as `unconfirmed` until the new service has reconciled it. Rooms of the dead service are rebuilt from disk and reconnecting clients only; their unsaved edits are lost exactly as when Local's process dies today, which P9's injected failure measures.

## Seams this needs in Local (M1 to M5), each behavior preserving in process

- **S1, the authority block as two functions per lane.** Extract `admitSave`, `admitReplace`, `admitRebase` (the decision half, returning `{ decision, logical, floor, reservation, artifacts }`) and `settleWrite` (the confirmation half) from `document-host.js:244-320`, `364-439`, `526-530`, `616`, `164-175`, `631-641`, plus `renderCheckpoint` from `764-808`. In process, the lanes call these and write the artifacts themselves, so Local's own `document-host` tests prove nothing changed. The service calls the same functions. Smaller than either seat's `prepareSave`, because the lane's writes and non-room decisions stay where they are.
- **S2, the room-owning routes as a factory.** Move the routes listed under `/v1/route/*` into a factory taking `{ ctx, authority, documentHost }` and returning an Express router, mounted by `createApp` in process and by the service in M19 (`server.js:810-1222`, `1570-1588`, `1724-1853`, `3290-3494`).
- **S3, the observer's authority half, fed by Go.** `root-observer.js:161-315`'s `_classifyHtml` and unlink handling as functions the service's `observe` handler calls with bytes Go read under its lock, with no chokidar.
- **S4, the recovered-copy writer injected.** `publishRecovered` is already injectable (`local-authority.js:7`, `:40`); in the service it collects the copy as an artifact instead of writing.
- **S5, the auto-name and checkpoint host calls.** `hosts.get(rootId).checkpoint(…)` (`local-checkpoint.js:82`) and the auto-name rename (`commands.js:179`) reach Go through the adapter in the service; no Local change beyond the adapter gaining `checkpoint`.

## Not decided here, for the reviewers

- Whether `admit` should be skipped for a page document with no open room and no recovery record, to save a round trip per save. This draft calls it for every page write, because only the service knows which rooms exist; the cost is one loopback call per save.
- Whether the live layer should split (Go's hub for the v1 lanes, the service for the authority's) instead of moving whole. This draft moves it whole, because with an authority Local answers every stream through it.
- Whether recovered copies and safety versions should carry digests the service computes, as the Astra seat proposed for every artifact. This draft has Go compute and record them.
